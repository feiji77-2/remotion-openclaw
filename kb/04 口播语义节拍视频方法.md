# 口播语义节拍视频方法

![[Assets/skill-showcase-v3-effects.jpg|820]]

## 核心方法

```text
口播 -> project:from-script -> 语义字幕时间轴 -> captionRange 场景 -> sourceText -> 语义 Beat -> 视觉状态机 -> 帧动画
```

旧方法通常是“数据进入模板，然后播放一次入场动画”。它适合数字、对比和架构图，但无法稳定承载十几秒的连续口播。

语义节拍方法把每个 Scene 继续拆成多个 Beat。字幕时间轴是唯一时间来源，每个 Scene 必须绑定连续的 `captionRange`，每个 Beat 必须绑定 `captionStartIndex/captionEndIndex`。每个 Beat 明确：

- 什么时候出现
- 当前最重要的关键词
- 使用哪个语义图标
- 触发什么强调动作
- 观众应该看哪里
- 主体组件进入哪个 `visualState`

## 叙事结构信号

新口播生成 Project 时，文案中的结构词会优先决定 Scene 的 `narrativeSignal`、`visualMode` 和 `layoutSignature`：

| 信号 | 视觉家族 | 默认主体构图 |
|---|---|---|
| 第一/第二/第三/首先/最后 | `spoken-ranking / step-flow` | `vertical-step-flow` |
| 左右/大约/接近/数字 | `spoken-takeaway / number-strip` | `metric-strip` |
| 等等/此外/另外/包括/清单 | `spoken-tags / tag-matrix` | `tag-matrix` |
| 但是/然而/不过/不是/而是 | `spoken-compare / compare-board` | `compare-board` |
| 因为/所以/因此/输入/输出/链路 | `spoken-process / focus-diagram` | `focus-diagram` |

`第一/第二/第三/最后` 是硬分镜边界，生成器禁止在最短片段合并时跨过去。`但是/另外/因为` 是软分镜边界，用于避免新稿全部挤进同一个中部画面。

## 三层画面

1. 顶部 `84-210px`：章节编号、主图标、标题和进度色条。
2. 中部 `240-1050px`：代码、编辑器、流程、对比或产品视觉证明。
3. Beat `1080-1480px`：关键词、图标接力、聚焦框和局部结论。
4. 字幕 `1630-1810px`：当前完整口播字幕。

关键词 Beat 放在主体与字幕之间，不重复整句字幕。

## 四层文字

| 层级 | 职责 |
|---|---|
| 章节标题 | 现在讲哪个能力 |
| 关键词 | 这一秒最重要的判断 |
| 解释标签 | 视觉证明中应该看哪里 |
| 字幕 | 完整承接口播 |

## 三层特效

- 持续层：扫描线、五组细线位移、确定性颗粒、景深框推进、色差边缘、焦点扫光和彩色图标慢漂。所有变化由当前帧计算，长镜头持续有呼吸。
- 节拍层：八种构图动作、前后图标接力、局部框选、证据堆叠、数值计数和结论爆发。入场 18-24 帧，退场 10-14 帧，每 2-4 秒发生一次语义变化。
- 转场层：章节色条横扫、图标接棒和 12 帧短闪切，与 Scene 转场同时工作。

特效必须能对应明确口播，不能只为了让画面更热闹。

## 八种 Beat 动作

| Action | 适用重音 |
|---|---|
| `stamp` | 章节名和强判断 |
| `spotlight` | 单一正向结论 |
| `trace` | 路径、输入输出和过程 |
| `compare` | 前后、正反和断点 |
| `counter` | 数量、通过率和可验证结果 |
| `stack` | 多项证据、步骤和组成 |
| `focus` | 需要局部框选的核心对象 |
| `burst` | 章节结论和能力释放 |

## 重音帧换算

Beat 不再凭感觉写秒数。先用 `captionRange` 得到 Scene 的全局起止帧，再从 Beat 绑定的字幕索引换算局部帧：

```text
sceneStartFrame = round(captions[captionRange.startIndex].startMs / 1000 * fps)
sceneEndFrame   = round(captions[captionRange.endIndex].endMs / 1000 * fps)
localStartFrame = round(captions[beat.captionStartIndex].startMs / 1000 * fps) - sceneStartFrame
localEndFrame   = round(captions[beat.captionEndIndex].endMs / 1000 * fps) - sceneStartFrame
```

新生成项目禁止按 Scene 长度平均铺 beat。旧项目缺少新字段时保留兼容，但新口播项目必须完整声明 `captionRange`、Beat 字幕索引、`visualState`、`motionPreset` 和 `placement`。

## Beat 数据接口

```ts
type SkillShowcaseBeat = {
  startFrame: number;
  endFrame: number;
  captionStartIndex: number;
  captionEndIndex: number;
  keyword: string;
  icon: SkillIconKey;
  action: SkillBeatAction;
  visualState: string;
  motionPreset: 'slow-rise' | 'scan-lock' | 'number-roll' | 'split-reveal' | 'card-regroup' | 'icon-relay' | 'focus-pulse' | 'flash-cut';
  placement: 'bottom' | 'body' | 'highlight';
  detail?: string;
  evidence?: string[];
  value?: string;
};
```

项目级硬规则：

- 每个 `skill-showcase` Scene 都必须有 Beat，开场、总览和结尾不能空。
- 全片第一个 Beat 必须从第 0 帧开始。
- 每个 Scene 的第一个 Beat 必须在局部 1 秒内出现。
- 每个 Scene 的最后一个 Beat 必须贴到 scene 结尾。
- 相邻 Beat 之间不能出现肉眼可见的长空窗。
- 每个 Beat 必须落在绑定字幕范围内，关键词必须来自绑定字幕或明确的 Beat 摘要。
- `outro` 只能在总结口播的 captionRange 开始后进入。
- 新口播 Project 必须写入 `layoutSignature`；视觉合同会拒绝连续三个 `skill-showcase` Scene 复用同一主体构图。

## 制作顺序

1. 锁定最终口播和音频。
2. 获取句级时间戳。
3. 运行 `project:from-script` 或 `production:build-project -- --family skill-showcase` 生成新 Project。
4. 每个 Scene 必须写入来自当前口播的 `sourceText`。
5. 根据内容转折切 Scene。
6. 将 Scene 时间换算为整数帧。
7. 写入每章 Beat。
8. 为 Beat 选择关键词、图标和 action。
9. 先检查视觉合同和关键帧。
10. 关键帧通过后才渲染完整 MP4。
11. 最终 MP4 必须通过成品守门脚本。

## 换稿入口

```bash
cd /Users/macos/OpenClaw/remotion-generated-video-project/remotion-video
npm run project:from-script -- --id new-topic --title "新标题" --script-file /absolute/path/script.txt --out examples/new-topic.json
npm run project:visual-check -- examples/new-topic.json
npm run project:qa-sheet -- examples/new-topic.json --out-dir out/new-topic-qa
npm run project:still -- examples/new-topic.json --frame 60 --out out/new-topic-f60.png --scale=0.5
```

这条入口会重新生成 `scenes[].payload`、`beats`、`labels`、图标映射和 `sourceText`。禁止只换 `captions` 或 `voice.m4a` 后直接渲染。
