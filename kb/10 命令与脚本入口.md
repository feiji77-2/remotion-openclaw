## 日常开发检查

```bash
npm run skill:gate
npm run project:from-script -- --id smoke-new-script --title 新稿工作流 --script "今天讲一个全新的知识库工作流。第一步，把输入统一成主题来源和结论。最后，沉淀成项目合同。" --out out/smoke-new-script.project.json
npm run project:visual-check -- examples/design-skills-showcase.json
npm run project:qa-sheet -- examples/design-skills-showcase.json --out-dir out/design-skills-showcase-qa-v2
npm run project:check -- examples/skill-showcase.json
npm run typecheck
npm test
```

用途：

- `skill:gate`：检查当前样片方法、资产、图标、Beat 和成品合同。
- `project:from-script`：从新口播生成新的 `skill-showcase` Project，避免复用旧样片 scene payload。
- `project:visual-check`：检查换稿项目的视觉合同，防止只换配音和字幕，并校验 captionRange/Beat 绑定。
- `project:qa-sheet`：为每个 beat 计算开头/中间/结尾帧；加 `--render` 时批量输出 QA 静帧和联系表。
- `project:check`：检查 Project schema、family、payload、资产和总时长。
- `typecheck`：检查 TypeScript。
- `npm test`：跑单元测试。

## Swiss V5 技术镜头入口

Swiss V5 是当前“技术博主类可复用镜头系统”的样片入口。它不是 V3/V4 的覆盖版本，也不是单次视频补丁；后续继续打磨时，应优先走这组命令和文档。

```bash
cd /Users/macos/OpenClaw/remotion-generated-video-project/remotion-video

npm run swiss:v5:build
npm run project:check -- examples/swiss-skill-spoken-v5-workbench.json
npm run project:qa-sheet -- examples/swiss-skill-spoken-v5-workbench.json --out-dir out/swiss-v5-workbench --render --scale=0.35
npm run swiss:v5:render
bash scripts/verify-render.sh examples/swiss-skill-spoken-v5-workbench.json out/swiss-skill-spoken-v5-workbench.mp4
```

用途：

- `swiss:v5:build`：生成当前 V5 Project JSON。
- `project:check`：检查 V5 Project 合同、时间线、family、资产和 payload。
- `project:qa-sheet --render`：生成 22 个 beat 的关键帧和联系表，用来先看“是否连续重复、是否像真实技术讲解”。
- `swiss:v5:render`：输出当前 V5 竖屏成片。
- `verify-render.sh`：检查 MP4 能否解码、规格是否符合 Project。

当前 V5 主要产物：

```text
examples/swiss-skill-spoken-v5-workbench.json
out/swiss-skill-spoken-v5-workbench.mp4
out/swiss-v5-workbench/all-22-midpoints-large.jpg
```

如果要快速审“22 个镜头是不是一眼能看出差异”，优先打开：

```bash
open /Users/macos/OpenClaw/remotion-generated-video-project/remotion-video/out/swiss-v5-workbench/all-22-midpoints-large.jpg
```

## 配音生成链路

```bash
npm run tts:project -- examples/skill-showcase.json --out tmp/tts-chain-smoke.m4a
```

用途：

- 读取 Project JSON 的 `captions`。
- 拼接口播文本并按约 500 字分段。
- 调用 Qwen TTS 生成每段音频。
- 下载临时 WAV。
- 用 FFmpeg 合并为单个 M4A。
- 输出音频时长，并和 Project 总时长比较。

依赖：

- `.env.local` 或 `.env` 中必须存在 `DASHSCOPE_API_KEY` 或 `QWEN_TTS_API_KEY`。
- 本地必须有 `ffmpeg` 和 `ffprobe`。

正式替换当前样片配音时可以省略 `--out`，脚本会默认写入 Project JSON 当前 `voiceAssetId` 对应的 public 音频资产：

```bash
npm run tts:project -- examples/skill-showcase.json
```

当前实测结论：

- TTS API、下载、合并链路可以跑通。
- 现有成片音频链路正常：`skill:verify` 能识别 AAC 音轨。
- 从 captions 直接重新生成的 Qwen 配音约 `149.920s`，当前项目时间线约 `121.633s`，不能直接替换生产音频。
- 如果重新配音，必须同步重算 `captions`、Scene duration、Beat start/end，或先做明确的时长适配策略。

## 换稿防污染

```bash
npm run project:visual-check -- examples/design-skills-showcase.json
npm run project:check -- examples/design-skills-showcase.json
npm run project:qa-sheet -- examples/design-skills-showcase.json --out-dir out/design-skills-showcase-qa-v2
npm run project:still -- examples/design-skills-showcase.json --frame 120 --out out/design-skills-showcase-fixed-intro-f120.png --scale=0.5
```

新口播不能只换 `captions` 和 `voice.m4a`。必须同步重写 `scene.payload` 的标题、品牌、图标、产品映射、`captionRange` 和 Beat。

正确换稿命令：

```bash
npm run project:from-script -- --id new-topic --title "新标题" --script-file /absolute/path/script.txt --out examples/new-topic.json
npm run project:visual-check -- examples/new-topic.json
npm run project:check -- examples/new-topic.json
npm run project:qa-sheet -- examples/new-topic.json --out-dir out/new-topic-qa
npm run project:still -- examples/new-topic.json --frame 60 --out out/new-topic-f60.png --scale=0.5
```

如果使用生产目录：

```bash
npm run production:build-project -- projects/new-topic --family skill-showcase
```

`project:still` 和 `project:render` 已接入视觉合同检查；污染项目会在渲染前失败。
