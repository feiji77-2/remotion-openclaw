## 当前一句话

```text
新口播/字幕 -> project:from-script -> Project JSON -> visual contract -> UltimateVideoV2 -> Scene + Semantic Beat -> QA -> MP4 -> Verify
```

这个项目的核心不是“用 Remotion 拼几个模板”，而是把完整口播拆成章节 Scene 和语义 Beat，再把关键词、图标、局部高亮、字幕、音频和成品验证绑定到同一条帧时间线上。

## 最重要的决策

- Remotion 运行时只负责确定性渲染，不负责搜索、LLM、TTS 或截图。
- Project JSON 是唯一运行时输入。
- 新口播必须先生成新的 Project JSON，不能从旧样片只替换 captions/audio。
- Scene 表示章节，Beat 表示章节内语义事件。
- 每个新稿 Scene 必须带 `sourceText`，并且 `sourceText` 来自当前口播。
- 字幕承接完整口播，关键词只强调当前判断，两者不重复整句。
- 先检查关键帧，再渲染完整 MP4，最终成片必须通过 `skill:verify`。
- 后续开发必须遵守 `remotion-video/docs/development-code-constraints.zh-CN.md`。
- 换口播必须通过 `project:from-script` 或等效流程同步更新 `scenes[].payload`，并通过 `project:visual-check`。
- Swiss V5 之后的技术讲解视频必须先判断语义，再选 Lens，再落到真实 Shot；不能只堆黑底框框、文字和数字。
- 渲染成功不等于可交付；必须先看 22 Beat 或对应节拍接触表，确认没有连续重复镜头。

## 成品守门

```bash
cd remotion-video
npm run skill:gate
npm run skill:render
npm run skill:verify
```

`skill:gate` 约束 Project、音频、字幕、Beat、图标和资产；`skill:verify` 在此基础上检查最终 MP4 的 H.264 视频流、AAC 音频流、时长、画幅和完整解码。
