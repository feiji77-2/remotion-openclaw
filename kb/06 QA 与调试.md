# QA 与调试

## 固定验收顺序

```text
Visual Contract -> Project Check -> Typecheck -> Tests -> QA Sheet Manifest -> 关键帧/联系表 -> 完整 MP4 -> Verify
```

不要在 Project 合同或关键帧还不稳定时反复渲染两分钟完整视频。

## 0. 成品守门

```bash
cd remotion-video
npm run skill:gate
```

检查：

- 样片真源是否仍是 `examples/skill-showcase.json`
- 9 个章节和 3649 帧是否保持一致
- `editorial` 字幕、必需语音和本地资产是否完整
- 57 个语义 Beat是否覆盖 8 种 action
- 首个 Beat 是否从第 0 帧开始
- intro、overview、outro 是否也有 Beat
- 12 类图标包、76 个 SVG 和 Lucide 许可证是否完整

## 1. Project Check

```bash
cd remotion-video
npm run project:check -- examples/skill-showcase.json
npm run project:check -- examples/design-skills-showcase.json
```

检查：

- schema
- family 注册
- payload
- scene captionRange 是否与字幕帧对齐
- beat captionStartIndex/captionEndIndex 是否落在 scene captionRange 内
- beat 关键词是否来自绑定字幕或明确摘要
- Beat 范围和排序
- 资产路径
- 总帧数

## 2. 工程检查

```bash
npm run typecheck
npm test
```

当前测试覆盖 Project 编译、非法 family、资产路径、转场、`skill-showcase` 和 Beat 边界。

## 3. QA Sheet

```bash
npm run project:qa-sheet -- \
  examples/design-skills-showcase.json \
  --out-dir out/design-skills-showcase-qa-v2
```

默认只生成 `manifest.json`，不渲染图片。manifest 会列出每个 beat 的开头、中间、结尾三帧。

需要批量渲染联系表时：

```bash
npm run project:qa-sheet -- \
  examples/design-skills-showcase.json \
  --out-dir out/design-skills-showcase-qa-v2 \
  --render \
  --scale=0.35
```

每个长章节至少检查：

- 章节头是否稳定
- 主视觉是否完整
- Beat 关键词和图标是否正确
- 字幕是否位于安全区
- Beat 与字幕是否重复或遮挡
- 连续三个章节是否复用了同一主体构图
- `manifest.json` 中的 `layoutSignature` 是否连续变化，`narrativeSignal` 是否匹配口播结构词
- 浅色区文字对比度是否足够
- 主体组件是否随 beat 切换 `visualState`

## 4.1 Swiss V5 技术镜头附加验收

Swiss V5 的核心不是“能不能渲染”，而是“22 个语义镜头是否像技术博主在讲解一个真实系统”。所以它必须比普通样片多看一层：Lens / Shot / 语义节拍是否成立。

```bash
cd /Users/macos/OpenClaw/remotion-generated-video-project/remotion-video

npm run swiss:v5:build
npm run project:check -- examples/swiss-skill-spoken-v5-workbench.json
npm run project:qa-sheet -- examples/swiss-skill-spoken-v5-workbench.json --out-dir out/swiss-v5-workbench --render --scale=0.35
npm run swiss:v5:render
bash scripts/verify-render.sh examples/swiss-skill-spoken-v5-workbench.json out/swiss-skill-spoken-v5-workbench.mp4
```

必须人工看：

- 22 个 beat 是否都有明确 Lens，而不是连续复用同一个框框模板。
- 主视觉 Hero Visual 是否负责“技术解释”，下方 Semantic Beat Animation 是否只负责“语义击打”，两者不要重复表达同一个东西。
- 连续 3 个镜头不能看起来像同一套排版换文字。
- 字幕上方的语义节拍动效不能压到底部字幕安全区。
- 数字、英文、中文都不能溢出，也不能靠“缩小一切”糊弄过去。
- 黑色面板、右侧检查器、大字数字只允许在语义需要时出现，不能成为所有镜头的默认答案。

## 常见问题

### 所有中文字幕同时出现

原因：把连续中文句子交给通用 TikTok 分页策略。竖屏口播应使用 `editorial`，逐条 Caption 渲染。

### 章节前两秒后不再变化

原因：只有 Scene 入场动画，没有语义 Beat。检查 `payload.beats`。

### 图标空白

检查：

1. `icon` 是否在 schema 枚举中。
2. `public/projects/skill-showcase/icons/` 是否存在 SVG。
3. 是否使用 `Img + staticFile()`。

### Beat 没出现

检查 Beat 使用的是 Scene 局部帧，不是全片帧。

### Beat 遮挡字幕

Beat 位于 `1195-1495px` 区域，editorial 字幕位于底部安全区。不要把关键词构图继续下移。

### 同一种风格连续出现很多遍

原因：只有统一 Hero 容器，没有真正的 Lens / Shot 差异。比如“开源信号”“扫描检测”“系统形变”“路径流动”都被做成了相似的框、文字和数字。

处理：

1. 先看 22 beat 联系表，而不是只看完整视频。
2. 给每个 beat 标注 Lens：它到底是数据聚合、界面扫描、代码证据、架构拓扑，还是系统变形。
3. 主视觉只表达技术逻辑，语义节拍只做短促强调，不要上下两块都做同一个意思。
4. 相邻镜头强制换排版方式、运动方向、主元素类型和颜色重心。
