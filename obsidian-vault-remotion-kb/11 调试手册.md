# 调试手册

## 先记住 5 个真源

- workflow 主入口：`remotion-video/scripts/run-search-to-ultimate.mjs`
- Step-04 转 scene：`remotion-video/src/data/storyboardLoader.ts`
- family / timing / transition 真源：`remotion-video/src/data/registry.ts`
- 导演层真源：`remotion-video/src/data/shotGrammar.ts`
- 最终渲染入口：`remotion-video/scripts/render-ultimate-scene.mjs`

## 60 秒排障流程

1. 先判断坏在哪一层：`workflow / images / voice / render / verify`
2. 不要直接盲跑全链路，先用 `--dry-run`、`still`、`540p` 把问题缩小
3. 先验证 `step-04.json` 是否正确，再验证 MP4，不要反过来猜
4. 任何“时长不对 / 黑帧 / 结尾拖空”都先查 `shots[].frames` 和 `payload.meta.totalFrames`

## 症状速查

| 症状 | 第一检查点 | 直接命令 | 正常信号 | 常见根因 |
|---|---|---|---|---|
| workflow 跑完但没有成片 | render 是否被跳过 | `node remotion-video/scripts/run-search-to-ultimate.mjs "主题" --resume` | 日志出现 `[render]` 段 | 使用了 `--no-render`，或 render 阶段失败 |
| 分镜看着不对 | Step-04 是否已变更 | `node remotion-video/scripts/render-ultimate-scene.mjs --config <step-04.json> --dry-run` | 每个 shot 都能列出 `id / family / frames` | `step-04.json` 不是当前版本，或 family 字段错 |
| 只想先看画面静帧 | Step-04 输入合法 | `node remotion-video/scripts/preview-quick.mjs --config <step-04.json> --mode still` | 生成预览目录 | 配置格式不被识别，或 shot 数据为空 |
| 浏览器起不来，根本不渲染 | 本机浏览器环境 | `node remotion-video/scripts/doctor-render-env.mjs` | `Render environment looks healthy` | Chrome/Chromium 路径缺失，或当前环境阻止浏览器启动 |
| MP4 存在但时长不对 | 最终合同校验 | `node remotion-video/scripts/verify-render-output.mjs --step4 <step-04.json> --video <out.mp4>` | `render contract verified` | Step-04 meta 错、ffprobe 不可用、渲染截断 |
| 没有语音文件 | qwen-tts 是否正常 | `node remotion-video/scripts/voice/qwen-tts-voice.mjs list` | 返回 voice 列表 JSON | 环境变量缺失、音色名错误、API 不通 |
| Storyboard QA 没有图片 | QA 输出路径 | `node remotion-video/scripts/run-search-to-ultimate.mjs --project-id <id> --resume --with-storyboard-qa` | `projects/<id>/qa/storyboard/` 下有图 | 只生成了主链路图，没有开启 QA 支线 |
| 分镜图生成了但没进成片 | 资产写入路径 | 查 `public/assets/<projectId>/images` 和 `project.json` | `imageUrl` 指向 public 资产 | 只跑了 QA mode，未写回主链路资产 |

## 四条排障主线

### 1. Workflow 线

目标：确认 Step 1-6 有没有产出可消费的数据。

建议顺序：

1. 先看 `projects/<projectId>/steps/`
2. 重点看 `step-03.json`、`step-04.json`、`step-05.json`、`step-06.json`
3. 如果怀疑字段漂移，回到 `remotion-video/server/workflow/skillRegistry.js`

你最该盯的字段：

- Step 3：`copy.body[]`、`storySpine`
- Step 4：`shots[]`、`sceneFamily`、`frames`
- Step 5：`prompts.byShotId`
- Step 6：`voice.script[]`、`voice.totalDuration`

### 2. Render 线

目标：确认 `step-04 -> scenes -> mp4` 这条链没有断。

先跑：

```bash
cd /Users/macos/OpenClaw/remotion-generated-video-project/remotion-video
node scripts/render-ultimate-scene.mjs --config projects/<projectId>/steps/step-04.json --dry-run
```

这里如果 dry-run 打印出来的 family、frames、duration 就不对，说明问题在数据层，不在 Remotion 层。

### 3. Preview 线

目标：在不跑完整 1080p 成片前，先低成本看画面。

```bash
node scripts/preview-quick.mjs --config projects/<projectId>/steps/step-04.json --mode still
node scripts/preview-quick.mjs --config projects/<projectId>/steps/step-04.json --mode sheet
node scripts/preview-quick.mjs --config projects/<projectId>/steps/step-04.json --mode 540p --out previews/check.mp4
```

经验规则：

- `still` 适合看版式和 family 选型
- `sheet` 适合扫全片节奏是否单调
- `540p` 最接近真实出片

### 4. Verify 线

目标：防止“视频能播但合同已坏”。

```bash
node scripts/verify-render-output.mjs --step4 projects/<projectId>/steps/step-04.json --video out/<file>.mp4
```

它实际校验的是：

- 最终 MP4 文件存在且非空
- ffprobe 得到的帧数接近 `meta.totalFrames`
- ffprobe 得到的时长接近 `meta.totalDuration`

## 你最常遇到的坑

### `step-04.json` 能打开，但渲染还是错

原因通常不是“Remotion 抽风”，而是下面三种之一：

- `shots[].frames` 和 narration 实际节奏不匹配
- family 对了，但 `visualProps` 缺关键字段
- `payload.meta.totalFrames` 没随着 shots 更新

### 渲染脚本没报错，但成片不对

先分清楚你跑的是哪条路：

- `render-ultimate-scene.mjs`
  这是 Step-04 数据驱动真源
- `render-project.mjs`
  这是 render-props / project 包装渲染
- `preview-quick.mjs`
  这是调试预览，不是完整验收

### `snapshots.mts` 不是全量真实回归

当前事实：

- 已覆盖 20 个 family 的回归脚手架
- 只有前 8 个 family 是完整 fixture
- 其余 family 仍有 stub fixture

所以：

- 它适合发现“画面明显变了”
- 不适合作为唯一质量门禁

```bash
node scripts/run-search-to-ultimate.mjs --project-id <projectId> --resume --with-storyboard-qa
```

## 排障时的原则

- 不要一上来重跑全链路
- 不要看到渲染问题就直接改组件，先确认输入数据
- 不要把 `outline` 兼容链路当真源
- 不要只看“有没有视频”，要看“帧数和时长是否对合同”
